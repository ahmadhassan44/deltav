What goes in

SectionAnswer this
ProblemWhat goes wrong today, in two sentences.
UsersWho does the work, and how many of them.
CostHours, errors or revenue lost each month. Rough is fine.
ProcessThe steps today, exceptions included.
SystemsEvery tool and file involved. Note which have APIs or exports.
DataWhere records live, how clean they are, who owns them.
DoneWhat changes when it works. A number if you have one.
ConstraintsBudget range, deadline, compliance, hosting.
OwnerOne person who answers questions and decides.

What stays out

  • Feature lists copied from competitors.
  • Tech stack choices, unless a constraint forces one.
  • Screen designs. A sketch of today's process tells a developer more.
  • Phase-two wishes. Name them in one line, then park them.

Describe the problem. Let the developer propose the solution, then judge the proposal.

One-page template

  1. Problem. Today, [who] spends [time] on [task] because [cause].
  2. Users. [Number] people in [roles].
  3. Cost. About [hours / errors / revenue] per month.
  4. Process. [Step 1] → [step 2] → [step 3]. Exceptions: [list].
  5. Systems. [Tool], [tool], [spreadsheet]. APIs: [yes / no / unknown].
  6. Data. Lives in [place]. Quality: [clean / messy / scattered].
  7. Done. [Task] takes [time] instead of [time], or [error] stops.
  8. Constraints. Budget [range]. Live by [date]. Must [comply / host / integrate].
  9. Owner. [Name], [role]. Available [hours] per week.
